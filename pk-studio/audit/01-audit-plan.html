3. Оси аудита (как идём)

Ось A — Навигация и экраны

  • Каждый пункт меню → открывается ли панель.
  • Login / logout / lang / mobile sidebar.
  • Dash shortcuts vs сайдбар (дубли).

Ось B — Кнопки и действия

  • Статические id в HTML → есть ли listener.
  • Динамические data-* (products/pins/home/blocks) → bind после render.
  • «Мёртвые» bindings (listener без кнопки) и кнопки без handler.

Ось C — Данные и сохранение

  • Draft save (D1) vs Publish (GitHub).
  • Валидация ссылок/картинок на Save.
  • Legacy-поля (amazonUrl) vs links[].

Ось D — Preview

  • Есть ли offline/draft preview (Articles/Products да; Home/Pins — нет).
  • Live vs Lab vs blob preview.
  • Картинки Worker URL vs Pages path.

Ось E — Паритет модулей

  • Что умеют Articles, но нет у Products/Pins/Home (SEO gate, блоки, multi-store UI…).
  • Что мешает «молниеносно» чинить картинки/статьи/карточки.

Ось F — Безопасность / UX владельца

  • Owner checks, prefilled login, cache-bust, i18n holes.
  • Опасные one-click publish без гейтов.

5. Критерии «проблемы»

  • P0 Critical — ломает publish / деньги / доступ owner / данные теряются.
  • P1 High — кнопка не работает, preview врёт, картинка/ссылка уходит битой на live.
  • P2 Medium — неудобство, дубли UI, нет валидации, нет preview.
  • P3 Low / polish — i18n, cache-bust, мёртвый код, копирайт.

6. Формат отчёта аудита

В 02-audit-report.html каждая находка:

  • ID (A-01…), severity, модуль
  • Что сломано / чего нет (факт)
  • Где в коде (файл)
  • Почему важно для владельца
  • Решение (конкретный фикс)
