4. Находки и решения

P0Team A-01 · Owner-проверка сломана

Факт: sessionIsOwner() смотрит s.user.owner, а сессия кладётся плоско: { token, login, role, owner } в auth.js.

Файл: pk-studio/js/ops.js (~647), auth.js (~47–52).

Почему важно: invite/remove админов могут быть скрыты даже у owner — «я не могу управлять командой».

Решение: return !!(s?.owner || s?.user?.owner || s?.role === "owner"); + smoke-тест после login.

P1Home/Pins A-02 · Нет draft-preview

Факт: Articles и Products имеют blob-preview API. Home и Pins — только Live/Lab. Live = последний publish, не Cloudflare-черновик.

Почему важно: правки «Сохранить черновик» нельзя увидеть до Publish → страх и лишние коммиты.

Решение: POST /api/preview/home и /api/preview/pins по образцу products (template с GitHub/live + inject draft + banner). Кнопки «Проверить офлайн» в Home/Pins.

P1Home/Pins A-03 · Нет валидации affiliate-ссылок на Save

Факт: Products блокирует placeholder https://link.amazon/. Home Top picks и Pins products text — нет. Можно сохранить stubs и опубликовать.

Решение: общий isGoodBuyUrl() на Save Home/Pins; для Pins парсить links[]; предупреждение до Publish module.

P1Publish A-04 · Module publish без клиентского гейта

Факт: Articles → SEO gate → seo_ready. Home/Pins/Products → один клик Publish без проверки ссылок/картинок/пустых карточек.

Решение: preflight checklist в Publish (битые amzn, пустые image, TODO) с блокировкой или явной «Publish anyway».

P1Media A-05 · Удаление файла не чистит черновики

Факт: Media delete убирает файл из D1/списка, но пути в home/pins/products/articles остаются → битые картинки на live после publish.

Решение: перед delete — scan drafts на path/key; warn «используется в N местах»; опционально null-out references.

P1Media A-06 · В панели Media нет Upload

Факт: Upload только из карточек редакторов. Владелец не может «просто залить картинку в библиотеку».

Решение: кнопка Upload в Media + preferredName/SEO filename + копирование path в clipboard.

P2Pins A-07 · Multi-store только текстом

Факт: Products имеют UI buy-links. Pins — textarea Name | Amazon | url | …. Легко ошибиться форматом.

Решение: тот же buyLinksEditorHtml + список товаров пина как мини-карточки (не только textarea).

P2Home A-08 · Top pick = один Amazon

Факт: После multi-store в Products/Articles, Home carousel всё ещё одно поле Amazon.

Решение: links[] у top picks + render нескольких CTA на главной (или primary + secondary).

P2Articles A-09 · Live-статьи нельзя открыть в редакторе

Факт: Список «Уже на сайте» только для просмотра. Править опубликованную статью = нет пути «open from live».

Решение: «Импорт в черновик» из live HTML/slug или sync draft from GitHub page.

P2UX A-10 · Placeholder stubs размножаются

Факт: New product / top pick / blocks стартуют с https://link.amazon/ или https://amzn.to/ без кода.

Решение: пустой url + placeholder hint; Save/seo_ready блокируют пустое; не писать stub в JSON.

P2Ops A-11 · Мёртвые кнопки Back

Факт: ops.js вешает listeners на #btn-back-from-publish|seo|team|status|media — в HTML их нет.

Решение: удалить мёртвый код или вернуть кнопки «← Обзор» в шапки панелей.

P2i18n A-12 · Placeholders не переводятся

Факт: data-i18n-placeholder на art-title/dek есть, applyI18n меняет только textContent.

Решение: в applyI18n: если attr placeholder — ставить el.placeholder = t(key).

P2Media A-13 · Hardcoded Worker host в imgSrc

Факт: Studio всегда тянет media с production Worker, даже при local API :8787.

Решение: строить media base из PK_AUTH.API.

P3Security UX A-14 · Prefill логина owner в HTML

Факт: value="qwiqlyowner@pickora" в login form.

Решение: убрать value; помнить login в localStorage после успешного входа (опционально).

P3Cache A-15 · Разный cache-bust JS/CSS

Факт: CSS/app ?v=20261005a, часть скриптов всё ещё 20261003d/i → риск старого ops/i18n в браузере.

Решение: один STUDIO_ASSET_V на все script/link при каждом релизе Studio.

P3Copy A-16 · Fallback panel «скоро»

Факт: data-view="panel" говорит что Publish/SEO/Team ещё впереди — они уже есть.

Решение: текст «модуль не загрузился / ошибка» + retry.

P3Code A-17 · Мёртвый код

Факт: fileToDataUrl (app.js), duplicateAt (blocks.js), i18n productsBadAmazon неиспользуемый.

Решение: удалить или довести (duplicate block button).

P3Pins A-18 · Нет reorder пинов

Факт: Новые пины сверху (unshift), но нет ↑↓ как у products/top picks. Порядок на доске ещё и shuffle на live.

Решение: ↑↓ в Studio + опция «не шаффлить» на categories (или seed shuffle).

4b. Pass 2 — доп. находки (дешёвый dig)

Память агента: pk-studio/audit/FINDINGS.md (+ Agent Store). Ниже — новые ID после A-18.

P1SEO A-19 · listArticleDrafts без blocks

Факт: SEO-сканер в Studio читает d.blocks, а список черновиков API отдаёт только slug/title/status/affiliateLinks/cover — блоки не приходят → ссылки из блоков статей могут не попасть в очередь.

Решение: отдавать blocks (или link-extract) в list API, либо догружать каждый slug в loadSeo.

P3Media A-20 · Public GET media (by design)

Факт: GET /api/media/file/* без auth — нужно для <img> на live. Не баг само по себе, но ключи угадываемые.

Решение: задокументировать; позже signed URL / только публичный CDN path.

P2Security A-21 · links/check SSRF

Факт: сервер fetch’ит произвольные URL из body (для авторизованного админа).

Решение: allowlist доменов + блок private/link-local + лимит редиректов.

P2SEO UX A-22 · 401 → «0 ссылок»

Факт: loadSeo не проверяет res.ok.

Решение: fail + logout на 401.

P2SEO UX A-23 · Check только первых 20

Решение: батчи или явная подпись «проверено 20 из N».

P2Team A-24 · Audit actor = target

Решение: в audit_log писать login актёра; target — в detail.

P2Team A-25 · Trim OWNER_* рассинхрон

Решение: один helper trim для login и requireOwner.

P2Media A-26 · Delete всегда ok

Решение: 404 если строки не было.

P2Media A-27 · ON CONFLICT overwrite

Решение: insert-only + суффикс / 409.

P2Media A-28 · Delete не трогает GitHub

Решение: удалять wp-content blob при наличии token.

P2Auth A-29 · Offline me() фейковый user

Решение: при сетевой ошибке возвращать null, не синтезировать user.

P2Ops A-30 · Нет единого 401→logout

Решение: shared fetch wrapper во всех ops.

P2Auth API A-31 · verifyPassword без null-guard

Решение: валидировать hash; 401 вместо 500.

P1Publish A-32 · absUrl pins/products без media rewrite

Факт: Home publish переписывает /api/media/file/… на Worker. Pins/Products — нет → битые картинки на Pages при относительных media-путях.

Решение: общий helper как в publish_home.js.

P1Home A-33 · Смена языка сбрасывает Top picks

Факт: #btn-lang делает readHomeForm + renderHomeEditor без readTopPicksForm.

Решение: вызвать readTopPicksForm() перед render.

P2SEO gate A-34 · Richtext ссылки не в collect

Решение: парсить affiliate URL из bodyHtml/richtext.

P2Publish home A-35 · Пустые top picks → stale HTML

Решение: патчить пустой shell при length 0.

P2Pins A-36 · Filters не редактируются

Решение: UI редактора filters.

P2Articles A-37 · Reopen сбрасывает черновик

Решение: сохранять current или confirm.

P2Articles A-38 · Cover preview без imgSrc

Решение: тот же normalizer, что у Home/Products.

P2Products A-39 · replaceProductCards ломается без кнопок

Решение: endRe без btns + Studio требует ≥1 link.

P3Articles A-40 · Live list cap 20

Решение: pagination/search.

P3Blocks A-41 · html block без sanitize

Решение: sanitize/disallow on publish.

P3Home A-42 · Дубли URL в Latest Reviews

Решение: warn/block duplicates.

P2Products A-43 · Save без проверки страницы хаба

Решение: preflight существования {hub}/index.html до Publish.
